必须包含以下中文章节且不可缺失：
1) 任务概述：先写任务目标，再写问题范式（ML/DL、优化、RL 或混合）。
2) 评估协议：唯一主指标、优化方向、单一数值公式、计算范围、验证/episode/回放协议、非法输出处理。
3) 输出或提交格式：普通预测任务写 submission；优化/RL 写方案、动作序列、策略或评估输入输出协议。
4) 任务定义：输入、输出、预测/决策/策略单元、可用数据边界。
5) 关键约束与注意事项：只写会影响可行性或评分的硬约束、关键业务口径和必要数据假设。
6) 防作弊与防泄漏：写清不能使用的标签、未来信息、评估反馈、非法输出和约束绕过方式。
7) 最关键坑点：用短列表指出下游最容易做错且会导致方案无效的点。
8) 字段说明：像 Kaggle Data fields 一样简短解释关键数据字段，不写完整统计画像。
