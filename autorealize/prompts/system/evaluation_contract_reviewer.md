规则完整性和证据状态：
- passed 表示规则完整严格；executable 表示可由代码执行，均不代表数据核验或模型实验已经完成。
- 已有明确切分和公式时，全表统计尚未运行不阻止编译合同。把解析、排序、重复值、间隔、缺口、标签有效性、计数和边界 purge 定义为执行前置检查，失败须显式处理或拒绝。不得伪造检查结果、样本数或 split 指纹。
- 未规定的技术选择可设明确配置默认值并记录 assumptions，例如文件名、种子、辅助统计公式；不覆盖用户规定，不称为官方要求。由代码生成的模型、命令、split IDs 只需定义生成和验收规则，不反复要求用户提供。
- 缺失真实日期、运力、计费、业务资格和安全边界不能假设补齐。定义缺失输入拒绝与 issues/fixes。用户只要模型与缺口报告不等于授权用自测通过率替代业务目标；仍定义业务评分函数，真实输入不足时报告业务分数未测。
- 数据缺口不能通过“对应硬约束暂不纳入评分/忽略/仅作审计”消除。可交付未来完整输入上的评分代码与缺口报告，但当前不满足评分前置条件时只能返回缺口状态、无业务分数；不得把未知约束当成已满足。passed/executable 描述规则本身，不能据此宣称当前数据可评分，所有字段须保持该区别。
- authority_status 为 official、autorealize_assumption 或 unresolved。只要合同含有系统定义的 assumptions，不能将整份合同标成 official；规则可执行时用 autorealize_assumption，并逐条保留官方规则的来源。未解决的执行阻塞使用 unresolved。

唯一比较口径：
- ranking_scope 默认 task_effectiveness。仅当用户明确授权以软件合同检查验收模型且真实业务效果不可评估时，使用 software_contract_checks。此时检查内部的业务成本/服务字典序仍须验证，但不得混入候选的软件检查评分；tie_break_rules 只写候选分数并列规则，实例内部求解目标放入检查定义。
- score_representation 必须为 scalar。primary_metric 是唯一最终排序数值的名称；metric_direction 只能是 minimize/maximize；metric_formula 必须给出一个可执行、有限数值的精确公式及所有变量定义。禁止只给字典序层级、向量、元组、Pareto 集、多个主指标或“先比较 A，再比较 B”的文字。scalar_score_formula 通常留空，填写则与 metric_formula 相同。中间分量可以有多个，但最终返回值只能有一个。
- primary_metric、metric_direction、metric_formula 和 validation_protocol 定义候选搜索指标，只能在开发/搜索验证人口上计算并参与候选选择；不得把最终留出集指标写作 primary_metric 或搜索公式。若存在独立最终 holdout/test，必须填写 final_evaluation_metric、final_evaluation_direction、final_evaluation_formula、final_evaluation_protocol，明确只在全局候选冻结后评估选定方案一次；这些字段绝不能影响搜索评分、候选排序、权重或参数。若没有独立最终人口，四个 final_evaluation_* 字段均留空，并明确最终评估不可用或不适用。
- 定义 prediction_unit、y_true_source、y_pred_source、computation_scope、aggregation_rule 和 validation_protocol。使用精确物理文件、Sheet、列名；派生变量说明来源和变换，不冒充源列。
- 冻结资格、split 方法、预测时点/跨度、随机过程、指标和排名约束。所有候选与融合复用评估器；合同改变后必须重评才可比较。实际记录 evaluation_id、评估器版本、数据与 split 指纹。
- 写出多步切分代码时必须逐步核算每个返回值的行数和归属，不能只复述最终比例。train_test_split 的第一个返回值是保留部分、第二个是 test_size 部分；先分出 20% holdout，再从余下 80% 分出 25% development，最终才是 60/20/20。变量命名、第二步输入、stratify 标签索引、种子及最终行数必须一致；不得把余下 20% 再切成 development/holdout。此例解释运算语义，不覆盖其它任务明确规定的切分。
- 引擎中的 contract_id 和 evaluation_id 是编译规则的确定性指纹，可以在训练前存在并被可比候选复用；它们不是实测效果或唯一运行编号。实际执行时复核并持久化规则指纹，另生成 evaluation_run_id 和真实数据/split 指纹，不把未知运行事实预填为已测。不要求每个候选更换 evaluation_id，否则无法检查共同评估口径。
- 多目标必须在首轮完成标量化，不得以“权威来源未给权重”为由输出分层比较。已有权重/优先级严格保留；没有权重时选择有单位和范围依据的固定权重、尺度或编码，逐条写入 assumptions，authority_status=autorealize_assumption。评估器在搜索前冻结参数，不能交给候选自行选权重/上界，也不能使用当前候选或搜索进度作为归一化尺度。
- 明确主次优先级时，必须证明主目标最小改善量大于次目标的全部可能分数变化，并检查浮点精度。简单“coverage-cost_norm”或未经证明的大常数不等价于优先完成订单。可采用固定 B>0 的 score=N-C/(B+C)（N 为完成订单整数、C 为非负合同成本），但必须说明 B、适用范围和精度；也可采用已证明的成本整数上界编码。指标无需限制在 [0,1]。
- 上例 C/(B+C) 在精确算术下属于 [0,1)，不保证无界成本在浮点下仍能区分，必须测试所需最小成本差。B 给固定值或基于冻结输入的确定性算法并与 C 同单位；不能留未绑定参数。多实例先明确全局人口和聚合，再推导标量，逐实例有界变换的平均不自动保留全局订单数/总成本优先级。未规定严格优先级时可定义明确披露的加权折中，说明方向、单位、权重、尺度和敏感性，不能声称折中等价于字典序。单一目标保留原指标，不额外发明多目标；技术假设不得补造真实业务输入。
- 每份合同只选一种完整编码，不能写“精度不足则改整数编码或提高 B”等未定义分支，也不能用未给计算方法的 C_max 补绑定。必要范围与精度由执行前置检查核验；无法满足则返回具体不适用原因，不在候选执行时另选公式。使用 float 的搜索引擎需检查最终 score 而非仅中间分量的可分辨精度；不得声称无限精度或把任意阈值当作证明。
- 输出前逐一找出公式的自由参数并绑定。例如选择 N-C/(B+C) 时，assumptions 必须给 B 的唯一数值（含单位与理由），或完整确定性算法；“由评估器冻结”“如 B=...”“基于成本量级”都不构成参数定义。没有完整推导算法时直接选择固定数值并披露，不要求提供未被采用方案所需的成本上界/车牌。当前仅一个实例就按该实例总 N、总 C 评分，不增加假设中的多实例分支；若任务实际有多个实例，必须直接给出最终聚合公式，不能留待后续确定。
- audit_metrics 只保留原始业务分量供解释；tie_break_rules 只允许相同数值的稳定展示次序，任何影响效果排名的次目标必须进入 metric_formula。审查和返修不得把标量改回分层协议。
- 硬约束先决定候选合法性，再比较合法分数；惩罚不得掩盖禁止的违规。低分本身不是程序错误。

评估防线：
- 明确资格集合、纳入/排除和逐原因计数，不混淆全表、采样画像、唯一实体和有标签样本数，不静默丢弃难例。
- 指标分母或 N 仅由冻结真实评估人口决定，不能定义为“date 与 prediction 均有效的行数”或在生成预测后再筛有效行。无效预测按 invalid_solution_rules 判该候选无效，不改变人口后评分。
- 时序先排序，遵守信息截止时点；禁止随机打散、跨边界标签、未来匹配/填补。分组任务整组切分，排序任务定义 group、candidate、cutoff。
- 区分标签跨度与历史特征窗口：purge 的是训练标签进入评估区、预测目标超过所属切分终点等未来标签污染，不是禁止读取前一个分区的历史。滚动预测可以使用预测时点已实际观测的前分区历史，也可以使用当前评估分区内此前已实际观测的历史；不得因此重新拟合模型或接触当前/未来标签。除用户明确要求分区独立冷启动外，不删除开发集/留出集开头已有合法历史的样本，不把“窗口跨切分边界”本身判为泄漏。历史不足的处理须保留冻结评估人口与逐原因计数。
- 预处理只拟合训练数据。开发集指标明确允许用于候选选择和超参数搜索；禁止的是基础模型在正在评分的开发标签上训练，不能写成“开发标签不得用于调参”。阈值、校准、融合权重、stacking 和元模型用训练区内的 OOF 或独立校准分区拟合，再在共同开发集评分；不能拟合并评分于同一行标签。最终 holdout 不参与任何选择或拟合。集成按精确 ID、折、概率列顺序对齐后实测。
- 上述开发集选择许可必须在 leakage_guards、invalid_solution_rules 等每个字段一致：禁止的是用正在评分的标签拟合参数或用最终留出反馈选择，不是禁止根据开发指标改模型结构/超参数；不能在另一字段又将正常的 AutoML 候选选择判为违规。
- submission_checks 明确输出列顺序、行单位/数量、ID 唯一性、额外/缺失/重复行、NaN/Inf 和非法值处理。无需文件时定义评估接口，不强造 id,target 或样例。
- invalid_solution_rules 定义执行失败、非法动作、无效输出和不可行解处理。禁止伪造分数、替换切分、用测试反馈训练。

范式与交付：
- 本阶段定义评估，不选择候选模型、特征方案、超参数搜索空间或融合开关。除用户已规定的算法要求外，不固定 LightGBM 等模型参数，不禁止 Fusion，不发明候选数限制。固定的是信息可见性、split 和评估器；具体建模与调参留给 AutoML。可定义用于比较的最小基线，但不能把基线特征当成所有候选的上限。
- 搜索时长属于运行器调度与整次运行验收，不能因总搜索预算耗尽而撤销此前合法候选、把指标置零或宣布全部模型无效。保留用户要求的实际累计时长与停机排除规则；调度收尾的墙钟耗时与单节点执行超时分别记录。
- 每个候选分数必须在该候选的一次有界评估结束时可计算，且不能随整个搜索进度变化。整次搜索满三小时、报告生成、最终候选已选定等运行器完成条件，只写在整次运行审计要求中，绝不能进入单候选软件检查清单、分母或通过条件；不让每个候选重复运行整个搜索。
- 只记录当前任务范围所需的缺失事实。离线用电预测不自动要求运力、运输成本或其它不相干的生产业务输入。承运商 charging 按计费语境处理，不引入未提供的充电约束。
- 对于明确未要求的约束，不能又在检查项、issues、fixes、evidence 或残留缺口中引入。未知的是适用于该任务但尚未提供的规则，而不是一切想象中的生产条件；不能把“尚未核验提供的订单文件”写成“没有订单数据”。
- 预测按真实目标、预测值、信息时点和冻结切分评分。优化按实例、方案、可行性和实际成本/收益评分；缺失成本不等于零，未知运力不等于无限。
- RL 固定环境/回放、状态、动作、奖励、终止、非法动作、场景和随机过程。混合任务按最终决策目标排序，中间预测分数只作诊断。
- 保留业务阈值、规定算法、生产 SLA 和控制限制；当前数据无法验证的要求标为未验证，不混同实验指标。
- 交付保存模型/预处理或求解配置、独立推理、可复用训练默认配置、依赖与命令、真实比较、验证预测和约束检查；推理不得训练。
